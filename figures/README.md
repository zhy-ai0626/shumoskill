# 图表模板

**图是主要得分位，不是装饰。** 2022A 讲评「评阅中发现的问题」9 条里 **5 条与建模无关**，
全是"计算方法不清楚 / 结果不完整 / 没有很好地呈现结果 / 没有对结果进行分析 /
结果文件格式不对"。一等奖论文的图数中位是 **20 张**，表 9 张。

```bash
python figures/gallery.py            # 出全部范例（含灰度校样）
python figures/gallery.py 机理 数据  # 只出指定题型
```

**11 张里有 3 张要真题附件**（`01` 机理、`03` 数据统计、`05` 成分——
拿真数据画是有意的，同时验证了这套样式在真实量级下成立）。附件不随 skill 分发，
所以裸跑只出 **8 张**，另外 3 张会明确报"跳过"。要出全部：

```bash
export CUMCM_REPO=/path/to/数学建模     # Windows: set CUMCM_REPO=D:\Desktop\数学建模
python figures/gallery.py               # 其下应有 1_赛题与数据/
```

| 文件 | 用途 | 改不改 |
|---|---|---|
| `starter.py` | **拿来就改的绘图起手式**：六段最常用的图，只需替换 `load_data()` | **改这个** |
| `flow_pptx.py` | 生成**可编辑的 .pptx** 技术路线图（两页：总体 + 每问模板） | 改生成的 pptx |
| `cumcm_style.py` | 样式模块。中文字体、配色、字号、流程图与相关矩阵 helper、保存 | 别改 |
| `gallery.py` | 按题型的 11 张范例，同时是对样式模块的验证 | 别改 |
| `gallery/` | 生成的图，每张都配一份 `_gray.png` | 生成物 |

```bash
python figures/starter.py                    # 六段全出（内置合成数据）
python figures/starter.py --only 2           # 只出相关矩阵那段
python figures/flow_pptx.py --preview        # 出 pptx，并渲染一张预览确认排版
```

**赛前先裸跑 `starter.py` 一次。** 它同时是环境自检：中文字体、matplotlib、
Pillow（灰度校样）哪一样没配好都会在这里报出来，而不是等到第三天出图时
才发现图上全是方框。

守卫测试在 `tests/test_figures.py` 与 `tests/test_glyph_safety.py`：
色标是否钉在 [-1,1]、折线箭头两端是否平行、轴标签是否为空、第 9 个系列是否报错、
pptx 的连接线是否两端都绑住、图上的字符本机字体里有没有字形。
这几项的共同点是**画错了不报错**。

## 流程图为什么走 pptx 而不是代码

其余 10 张都是"数据决定长相"的图——数据一换图自己就对了，所以代码是最好的载体。
流程图不是：它的内容是**人的判断**（这道题分几步、哪一步反馈到哪一步），
72 小时里跟着模型改三四遍，每次都是挪一个框、改四个字。

这种编辑循环里 pptx 有一条别的格式都没有的优势：**connector 的两端锚在形状上**。
拖动任何一个框，连它的箭头自动跟随。SVG 在 Inkscape 里、HTML canvas 在浏览器里，
挪完框每一根线都要手动重连。加上 WPS 在参赛队里是默认装备——
pptx 是唯一"队友双击就能改"的格式。

| | PPTX | canvas / HTML | SVG | matplotlib |
|---|---|---|---|---|
| 拖框改字 | 原生形状 | 改代码 | Inkscape 可改 | 改代码 |
| **箭头跟着框走** | **是** | 否 | 否 | 否 |
| 队友能改 | WPS 人人有 | 要环境 | 要装 Inkscape | 要会 Python |
| 进论文 | 另存为 PDF（矢量） | 截图 | 直接进 | 直接进 |

`flow_pptx.py` 的幻灯片尺寸设成 **20×15 cm**（不是默认 16:9），所以
"另存为图片"导出的就是插图该有的比例，不用再裁一次。

matplotlib 版（`gallery.py` 的 `09`、`starter.py` 的第 6 段）保留，用于
"不装 Office 也要出图"和"要和其它图严格同风格"两种情况。两版取同一套
`FLOW_TINTS`，混用不会打架（有测试盯住）。

**已知限制**：`flow_pptx.py` 只生成文件、不渲染。`--preview` 会把 pptx 里的
真实坐标读回来用 matplotlib 重画一张 PNG，并量文字有没有挤出框——
但 PowerPoint 的折线连接器自己走直角，预览里一律画成直线。
**长相最终以 WPS 里打开为准。**

## 一等奖论文实际在画什么（44 篇官方展示实测）

`python _tools/analyze_figures.py --official` 从解析后的 markdown 里抽出 **759 条图题**统计：

| 事实 | 数字 |
|---|---|
| 每篇图片数 | 中位 **20**（A 题 20、B 题 26、C 题 19；范围 3–82） |
| 有几何/示意图的论文 | **61%**，有的话平均 4.9 张，最多 24 张 |
| 有流程图/框架图的论文 | **52%**，有的话平均 2.3 张（通常是"总体一张 + 每问一张"） |
| A 题图题里"几何/示意"占 | **35%**（最大一类） |
| B 题图题里"拟合/残差"占 | 9% |
| C 题图题里"对比/方案比较"占 | 14% |

### 看真图看出来的四件事

翻了三张接触印相（A/B/C 各 20 张带图题的真插图）：

1. **最大的一类不是数据图，是"把几何关系说清楚"的示意图**，而且多为**黑白线条画**：
   坐标系、法向量、角度弧、虚线辅助线、地平线阴影。范例 `08` 就是照这个画法做的：
   **分层色带分区 + 红色只给本图要讲的量 + 角画成弧 + 长度画成双箭头 + 虚线是辅助线**。
2. **同一张底图反复使用**（B 题里很明显）：无人机圆周编队画了三四次，
   每次只新增标注一个量。读者不用重新理解构型，注意力全在新东西上。**这条最值得学。**
3. **曲线图很朴素**——MATLAB 默认蓝红两色，没有任何修饰，
   但**轴标签都带单位**（"时间 s""位移 m""速度 m/s"）。花哨不是加分项，单位齐全是。
4. **图题写的是"这张图说明什么"，不是"这是什么图"**：
   "悬点 E 的位移图""最内层定日镜的年平均光学效率""年各类农作物总产量排名"。
   759 条图题里 42% 不含任何图类词。**照这个写**——图题是结论的一部分。

### 一处必须如实说的张力

C 题的一等奖论文里**饼图、环形图、旭日图用得不少**，可视化通行做法是反对饼图的
（角度比长度难比较）。这里不替评委下结论：**事实是它们拿了一等奖**。
本模块不提供饼图模板，但也不认为用了就会扣分——
真正被官方点名的从来是"没有结果文件""没有对结果进行分析"，不是图表形式。

## 灰度可读：低成本保险，不是硬门槛

先给数据。灰度打印后颜色只剩明度，实测本模块配色的相对亮度：

```
violet 0.073 · green 0.162 · blue 0.188 · red 0.216
orange 0.278 · aqua 0.323 · magenta 0.340 · yellow 0.435
```

最难分的几对：**aqua↔magenta ΔL=0.017、blue↔green 0.025、blue↔red 0.028**——
真打印出来基本同色。所以本模块把第二通道做成**默认而非选项**：

```python
cs.series_kw(i, "line")   # → 颜色 + 线型 + 标记，捆在一起
cs.series_kw(i, "bar")    # → 颜色 + 填充网格
```

**你没法只拿到颜色。** `cs.save()` 顺手出一份 `_gray.png` 供核对。

**但要修正一个此前过强的说法。** 本模块最初把"评委会打印"当成第一约束，
而 44 篇官方展示论文的证据是：**它们几乎没有为灰度做任何设计**
（大量彩色流程图、饼图、热力图），照样拿了一等奖。所以正确的定位是：

- 第二通道的**成本接近零**（线型/标记本来就该有——男性色盲约 8%），保留；
- 它**不是获奖的必要条件**，别为它牺牲颜色的表现力，也别把灰度校样当成硬门槛；
- 真正被官方反复点名的是**结果不完整、没有分析、结果文件格式不对**，不是配色。

## 按题型的范例

| 题型 | 范例 | 这类题的图该说明什么 |
|---|---|---|
| 机理/几何/运动 | `01` 场分布 + 剖面 | 空间量用**单一色相由浅到深**（绝不用彩虹）；剖面图回答"哪一维影响最大" |
| 工程反演/测量 | `02` 拟合 + **残差** | 只画"拟合得很好"没有说服力，**残差图才看得出系统性偏差**。2025B 演练正是残差里的结构暴露了观测量取错 |
| 数据/统计 | `03` 分组趋势 + 个体轨迹 | 同一对象多条记录时，**灰细线画出个体轨迹**，让读者看见观测不独立 |
| 统计决策 | `04` 枚举结果 + 翻转边界 | 交付的不是重算一遍数字，是**决策在哪里翻转** |
| 成分数据 | `05` 类型均值堆叠 + CLR 判别 | 统计必须在 CLR 之后做；堆叠条要**少而宽**，否则填充网格看不见 |
| 通用 | `06` 灵敏度龙卷风 | Stage 6 标准交付。**必须按影响幅度排序**，不排序等于没画 |
| 通用 | `07` 约束 + 目标 | 设计类的核心图：可行域、目标方向、最优点位置，一张说清 |
| 几何示意 | `08` 分层与标注 | A 题图题里最大的一类（35%）。黑白线条画，红色只给本图要讲的量 |
| 通用 | `09` 技术路线流程图 | **52% 的论文有**，`paper_skeleton.md` 的 `## 2.1 总体技术路线` 就是它的位置 |
| 通用 | `10` 相关矩阵 + 散点确认 | 热力图只给候选、不给结论；删指标之前必须看散点 |
| 通用 | `11` 描述统计三联 | 分布 + 分组箱线 + 逐列缺失概览，对应 Stage 2 Step 4 的产出 |

### 09 流程图：四条规矩

1. **层级靠位置和箭头，不靠颜色。** 颜色只标角色（输入/处理/建模/校验/交付），
   灰度稿里五种浅色塌成一片也读得懂，因为结构没依赖颜色。
2. **箭头连边中点，不连中心**（`b.s` → `b2.n`）。连中心的箭头会扎进框里压住文字，
   这是手搓流程图最常见的翻车点。多条边汇进同一个框时用分数锚点
   （`top(0.1) / top(0.5) / top(0.9)`）摊开，否则三个箭头尖叠成一团黑。
3. **反馈边画虚线**，用 `angle=(180, 90)` 走直角折线绕在主干外侧。
   有回检环的论文，评委看得出你真回检了。
4. **框里写"做什么"，不写"用什么"。** "跨问一致性回检"比"一致性模块"有信息。

`flow_arrow(angle=(a, b))` 两端方向平行时（如 `(-90, 90)`）折线没有交点，
matplotlib 会画出一条乱线且不报错——所以 helper 直接拦住。

### 10 相关矩阵：为什么不能随手 imshow

**`imshow(C)` 会按数据范围自动拉伸色标。** 若这份数据的相关系数都在 0.3~0.9，
中点就落到 0.6 上，**图上"看起来中性"的格子其实是强正相关**，而且不报错。
用顺序色（`SEQ`）则把 −0.8 和 +0.1 画成深浅之差，**符号信息直接消失**。
所以 `cs.corr_heatmap()` 把 `vmin=-1, vmax=1` 写死，超范围的输入直接报错。

**这张图在灰度下必然丢符号。** 实测灰度校样：ρ=−0.49 与 ρ=+0.78 都是中深灰，
色标本身塌成 V 形（两端深、中间浅）。这不是配色没调好——任何发散色映射到单通道
明度时，正负两侧本来就要在中点两边对称地变深。所以**数字标注就是这张图的
灰度第二通道**，`annot_min` 别关掉；矩阵大到标不下（>15 阶）时，
正确的做法是先合并/筛指标，而不是画一张彩色能看、黑白丢符号的图。

## 硬规矩

1. **绝不用双纵轴。** 两个量量纲不同就画两张图（见 `07`）。这是最常见的图表错误。
2. **坐标轴必须带单位。** `cs.finish()` 会强制要求 `xlabel`/`ylabel` 非空——
   无量纲量写"(无量纲)"。这是 Stage 9 的人工检查项。
3. **≥2 个系列必须有图例**；单系列不要图例框，标题里说清是什么。
4. **不要每个点都标数字。** 只标最值、拐点、结论点，用 `cs.annotate_value()`。
5. **文字用墨色，不用系列色。** 颜色的活是标身份，标身份的是旁边那个标记。
6. **顺序色是单一色相由浅到深，发散色的中点是灰。** 彩虹在灰度下完全乱序。
7. **最多 8 个系列，散点/气泡最多 3 个。** 超了 `series_kw` 直接报错——
   第 4 槽起黄与橙同框，正常视觉 ΔE 13.7 已低于 15 的地板。
   该做的是分面、合并成"其他"，不是继续加颜色。
8. **状态色（好/注意/严重/危急）专用**，不许拿来当第 9 个系列。

## 开发过程中被实测纠正的三处

留在这里，因为它们都是"看起来对、实际不对"的那类：

- **填充网格自己盖住自己**：第一版把 `edgecolor` 设成和 `facecolor` 同色，
  而 matplotlib 的 hatch 线正是用 `edgecolor` 画的——彩色稿勉强看得出，
  **灰度稿里整根条糊成一块**。改用画布色画网格。
- **形式选错**：成分那张第一版给 67 个样本各画一根堆叠条，条宽只剩 1px、
  网格完全不可见，而且 67 根条回答不了任何问题。改成按类型聚合的 2 根宽条，
  既能看清纹理，又直接回答了"成分随类型怎么变"。
- **标记密度**：900 个点的折线上打 900 个标记，标记就不再是区分通道而是噪声。
  `series_kw(..., n_points=n)` 会自动稀释到约 12 个，并让各系列错开起点。

## 配色出处

分类色板取自经验证的八槽固定顺序色板，不是随手挑的：
相邻对最差 CVD ΔE 9.1、正常视觉 ΔE 19.6，均过硬门槛（OKLab ×100）。
散点这类"任意两两同框"的形式只有前三槽能全对通过（CVD ΔE 9.2 / 正常 24.0）。
**槽的顺序本身就是色盲安全机制**，别重新排。
