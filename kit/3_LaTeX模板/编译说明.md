# LaTeX 模板编译说明

## 已实测通过

TeX Live 2026 + `xelatex`，产出 5 页 PDF，**0 错误 0 警告**，11 项合规检查全过：
A4 尺寸、第 1 页为摘要页、摘要未超一页、正文无目录、中文可提取、
AI 声明在参考文献之前且用官方原句、附录含源程序与支撑材料列表。

## 编译

```bash
xelatex -interaction=nonstopmode main.tex
xelatex -interaction=nonstopmode main.tex    # 跑两遍，第二遍生成交叉引用
```

本机已装好一份精简 TeX Live（含 xelatex + ctex），在 `D:\texlive-cumcm`：

```bash
export PATH="/d/texlive-cumcm/bin/windows:$PATH"
```

**注意**：TeX Live 装在 `D:\texlive-cumcm` 而不是资料库目录里，
因为**安装器不支持中文路径**——第一次装到 `_tools/texlive`（路径含"数学建模"）
时安装器静默失败，目录是空的、退出码却是 0。

## 字体：必须用 `fontset=windows`

模板第 17 行：

```latex
\documentclass[UTF8,12pt,a4paper,fontset=windows]{ctexart}
```

**别改回 `fandol`。** 实测教训：fandol 编译不报错、PDF 显示也正常，但
`FandolSong` 以 Identity-H 嵌入且**不带 ToUnicode CMap**，
结果是 PDF 里的中文**无法复制、无法检索**——用 pypdf 提取出来是
`ᄝՎแཿં໓ѓี` 这样的乱码。组委会要跑高相似度检测，这是实际风险。

换成 windows 后 SimSun/SimHei 的 ToUnicode 正常，同一份 PDF 能提取出
`在此填写论文标题 摘 要 本文针对……`。

在 Linux/macOS 上改 `fontset=ubuntu` / `fontset=macnew`，
**改完务必验证一次中文能不能从 PDF 里复制出来**：

```bash
python -c "from pypdf import PdfReader; print((PdfReader('main.pdf').pages[0].extract_text() or '')[:80])"
```
