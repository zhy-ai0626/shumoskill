# CUMCM 摘要信息模板

> 这是内容检查表，不是官方分段规则。`01_abstract.md` 只写摘要正文与关键词，不加顶层标题；最终格式以当届官方文件为准。

## 摘要要完成的任务

让只读这一页的人能够回答：

1. 题目中的核心对象、目标和关键约束是什么；
2. 每个子问题采用了什么真正使用过的方法；
3. 得到了哪些可在正文或结果文件中追溯的结论；
4. 如何验证结果，以及模型在哪些条件下会失效；
5. 这些结果能支持什么决策或推广。

**段落数别凑，按子问题数走。** 实测 86% 的一等奖摘要用「针对问题一/二…」逐问分段，
段落数 = 开场段 1 个 + 子问题数（+ 可选收尾段）。

字数有两个口径，**以 44 篇那一档为准**：

| 样本池 | p25 / p50 / p75 |
|---|---|
| **44 篇官方展示论文**（一等奖，见同目录 `摘要写法.md`） | **848 / 927 / 1010** |
| 59 份可提取样本（混合池，含非获奖） | 748 / 992 / 1146 |

两个数不一致是样本池不同，不是哪个算错了。落笔用 **848–1010** 这一档：它来自真正的获奖论文，区间也更窄。官方硬约束只有一条——**摘要不超过一页**；字数只是发现异常的参照。

> 字数达标却溢出到第二页时，先数行内公式的个数，别急着砍内容。
> 实测 680 字也能溢出（约 40 处行内公式所致）——排查顺序见 `摘要写法.md` §4.5。

## 可直接填充的正文骨架

```text
针对【场景与决策对象】，本文在【关键数据/资源限制】下解决【核心目标】。
题目被拆分为【子问题关系】，其中【最关键的现实约束】决定了后续模型边界。

对问题一，采用【模型/算法】处理【输入与目标】，并通过【求解器/验证方式】得到【可追溯结果 1】。
对问题二，在问题一的【上游产物与版本】基础上，引入【新增机制或约束】，得到【可追溯结果 2】。
对其余问题，分别使用【方法与关系】，避免只列模型名称而不说明它解决了什么。

计算结果显示：【结论 A + 数值 + 单位 + 参照】；【结论 B + 数值 + 单位】；【结论 C + 数值 + 单位】。
这些结论分别对应正文【章节/表/图/结果文件】，未完成复核的数字不进入摘要。

通过【留出验证/可行性检查/联合扰动/替代求解器等与模型风险匹配的方法】，模型在【有现实依据的范围】内保持【量化稳定性】；当【临界条件】出现时，【受影响的结论】不再可靠。

据此，本文提出【具体决策或工程含义】。模型可迁移到【明确场景】时，需要重新采集【数据】、替换【假设/约束】并复核【风险】。

关键词：【问题域】；【核心方法】；【验证方法】；【应用场景】
```

## 写完后逐项核对

- [ ] **每个「针对问题N」段都落到至少一个具体数值**（44 篇里 91% 做到了，是评委在摘要页唯一能核验的硬信息）；
- [ ] **没有写「模型评价 / 优缺点」**——只有 11% 的一等奖摘要这么写，那是正文独立一章的事（68% 的论文设了这一章，见 `小标题写法.md` §2）；
- [ ] **没有硬凑「创新点」**——只有 5% 提；2025 C023 写了，但它三条都能在正文找到对应章节。有货才写，否则正撞组委会点名的反模式；
- [ ] 算法名称写出来了（组委会连年点名批评「没有给出具体算法」）；
- [ ] 每个子问题都有“方法 + 结果”，而不是只写“建立了模型”；
- [ ] 所有数值都带单位或参照，并能定位到正文和保存的结果；
- [ ] 方法名称与实际代码、公式一致，没有用“改进”“混合”包装未实现的设计；
- [ ] 验证方式与模型风险匹配，不强制所有问题使用 LHS/Sobol；
- [ ] 至少说明一个适用边界或失效条件；
- [ ] 没有学校、队员、地区、指导教师或其他身份信息；
- [ ] AI 辅助内容已按当届规则在对应位置标注并进入使用台账；
- [ ] 关键词来自问题与方法，没有“数学建模”“科学合理”等空泛词。

## 常见失败信号

- 摘要数字与正文版本不一致；
- 把示例数值、预期提升或未运行结果写成事实；
- 把“模型名称很长”当成创新证据；
- 写“结果较好、模型稳健”，却没有基线、误差或扰动范围；
- 列出大量图表、公式或引用数量，却没有解释它们支持什么结论；
- 只写优点，不写结论的适用边界。
